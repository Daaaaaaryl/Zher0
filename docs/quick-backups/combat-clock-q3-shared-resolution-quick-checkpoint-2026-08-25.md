## Q3 — How is simultaneous/shared resolution represented in the clock?

### Approved simple rule

A **shared resolution** is when two committed actions are handled together because they happen at the same moment.

For the current combat foundation, **Clash is the main established example of a shared resolution**.

If both sides commit compatible attacks and Clash occurs, the two attacks are handled together as one shared interaction/resolution.

Possible results of that shared interaction may include outcomes such as:

- one side taking a hit;
- Stun;
- Flinch;
- Knockback;
- other later-defined consequences.

Those possible outcomes are **results/effects of the resolution**. They are not automatically separate shared resolutions by themselves.

### Important distinction

Effects such as Stun, Flinch, Knockback, interruption, or similar conditions are not automatically treated as their own shared resolution.

Example flow:

`Player action resolves`

`→ effect is applied to Enemy`

`→ Enemy's pending action is checked`

`→ if the effect prevents that action, the pending action is cancelled`

That is an ordinary consequence-and-revalidation flow, not a new shared resolution.

### Current scope

At this point, Z'her0 does **not** need a broader universal rule for every possible same-time interaction.

The current safe interpretation is:

> **Clash is the main current shared-resolution case. If another genuine same-time mechanic is designed later, it can be added then without reopening this Q3 answer unless it creates a real conflict.**

This does not forbid future mechanics from creating another shared resolution type.
